# v2.3.0 Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `zk-attendance-sdk@2.3.0` with the P0 correctness fixes and the two cheapest high-value P1 improvements identified in the NPM Package Review, without breaking any existing public API.

**Architecture:** No structural rewrite. Six small, independent changes layered onto the existing `ZKAttendanceClient` / `JTCP` / `JUDP` architecture: a wire-protocol bug fix, an ACK-error check inserted at the single `executeCmd` choke point in each transport class, corrected packaging metadata, an injectable no-op-by-default logger, and additive type exports.

**Tech Stack:** TypeScript (strict), Jest + ts-jest, tsup (dual CJS/ESM build), pnpm.

## Global Constraints

- Target version: `2.3.0` (minor, per SemVer — all changes are additive or bug fixes, no existing method signature changes).
- Every existing public method signature must remain unchanged; new parameters must be optional with backward-compatible defaults.
- Node engines floor: `>=18.0.0` (corrects the current, inaccurate `>=12.0.0`).
- All work must pass `pnpm format:check && pnpm lint && pnpm test && pnpm build` before being considered done.
- Follow existing code style: 2-space indent, Prettier + ESLint config already in the repo — do not introduce new tooling.
- Out of scope for this plan (deferred, see the full review): JTCP/JUDP deduplication, unifying TCP/UDP return shapes, `setUser` throwing instead of returning `false`, auto-reconnect, command queueing, fingerprint/template protocol coverage. Do not attempt any of these here.

### Task 1: Fix UDP real-time `userId` truncation bug

**Files:**
- Modify: `src/helper/utils.ts:174-179` (the `decodeRecordRealTimeLog18` function)
- Test: `tests/utils.test.ts`

**Interfaces:**
- Consumes: nothing from other tasks.
- Produces: nothing other tasks depend on — fully self-contained.

**Background:** `decodeRecordRealTimeLog18` reads `recordData.readUIntLE(8, 1)` for the user ID — only 1 byte, capping the value at 255. The function's own layout implies a 4-byte field: the very next line reads the timestamp from `subarray(12, 18)`, meaning the gap between offset 8 and offset 12 (4 bytes) is the actual user-ID field, not 1 byte.

    const buffer = Buffer.alloc(18);
    buffer.writeUInt32LE(300, 8); // userId spans bytes 8-11; 300 > 255 so a 1-byte read would truncate it
    buffer.writeUInt8(25, 12); // year -> 2025
    buffer.writeUInt8(6, 13); // month (1-indexed)
    buffer.writeUInt8(15, 14); // date
    buffer.writeUInt8(10, 15); // hour
    buffer.writeUInt8(30, 16); // minute
    buffer.writeUInt8(0, 17); // second

    const result = decodeRecordRealTimeLog18(buffer);

    expect(result.attTime).toEqual(new Date(2025, 5, 15, 10, 30, 0));

### Task 2: Reject on device ACK-error responses

**Files:**
- Modify: `src/constants/command.ts` (add `ERROR_ACK_COMMAND_IDS`)
- Modify: `src/helper/jtcp.ts:111-144` (the `executeCmd` method)
- Modify: `src/helper/judp.ts:114-145` (the `executeCmd` method)
- Test: `tests/jtcp.test.ts`, `tests/judp.test.ts`

**Interfaces:**
- Consumes: nothing from Task 1.
- Produces: `ERROR_ACK_COMMAND_IDS: Set<number>` exported from `src/constants/command.ts`. No other task depends on it.

**Background:** Every write command (`setUser`, `deleteUser`, `restart`, `powerOff`, `clearAttendanceLog`, `enableDevice`, `disableDevice`, `setTime`, `connect`) funnels through `executeCmd` in `JTCP`/`JUDP`. Today `executeCmd` resolves with whatever buffer the device sends back, even if that buffer's command ID is `CMD_ACK_ERROR`, `CMD_ACK_UNAUTH`, etc. Adding the check in this one place fixes it for every caller without touching each method individually.

We only treat unambiguous error codes as failures — `CMD_ACK_ERROR` (2001), `CMD_ACK_UNAUTH` (2005), `CMD_ACK_UNKNOWN` (65535), `CMD_ACK_ERROR_CMD` (65533), `CMD_ACK_ERROR_INIT` (65532), `CMD_ACK_ERROR_DATA` (65531). We deliberately exclude `CMD_ACK_RETRY` (2003) and `CMD_ACK_REPEAT` (2004) since their semantics aren't a hard failure and misclassifying them risks a behavior regression — flag this assumption if it surfaces in real device testing.

function buildTcpReply(
  commandId: number,
  payload: Buffer = Buffer.alloc(0),
  sessionId = 1,
  replyId = 1,
): Buffer {
  const inner = Buffer.alloc(8 + payload.length);
  inner.writeUInt16LE(commandId, 0);
  inner.writeUInt16LE(0, 2);
  inner.writeUInt16LE(sessionId, 4);
  inner.writeUInt16LE(replyId, 6);
  payload.copy(inner, 8);

  const prefix = Buffer.from([0x50, 0x50, 0x82, 0x7d, 0x00, 0x00, 0x00, 0x00]);
  prefix.writeUInt16LE(inner.length, 4);
  return Buffer.concat([prefix, inner]);
}

  return socket;

export interface ZKLogger {
  warn: (message: string) => void;
  error: (message: string) => void;
}

/** Default logger: does nothing. No files are written unless a logger is explicitly provided. */
export const noopLogger: ZKLogger = {
  warn: () => {},
  error: () => {},
};

/** Opt-in logger that preserves the SDK's pre-2.3.0 behavior of appending errors to a dated local file. */
export const fileLogger: ZKLogger = {
  warn: (message: string) => log(message),
  error: (message: string) => log(message),
};

## [2.3.0] - 2026-07-26
### Fixed
- Fixed a bug where UDP real-time attendance events truncated the user ID

  `ZKAttendanceRecordUdp`, `ZKRealTimeLogTcp`, `ZKRealTimeLogUdp`, and
  `ZKDeviceInfo` types for use in consuming TypeScript code.
